# 写作台 · dsh-writer-studio

给 DeepSeek Harness 用的**长篇小说写作插件**。右侧栏一个完整面板，对话里一套强制流程，解决三件事：

- **看不见前文**：每次动笔前 `writer_context` 都从磁盘重新组装上下文包（作品档案、文风卡、世界观、全部角色卡、最近 30 章梗概、上一章结尾原文、连续性账本）。
- **设定冲突**：设定与正文落盘，面板与工具读写同一份数据；角色卡、世界观、文风、字数区间不会随会话丢失。
- **写飞字数**：每章字数在开书时定死；保存时低于下限或高于上限直接拒绝，不存在“先写再删”。

## 功能

| 模块 | 内容 |
| --- | --- |
| 书籍 | 书名、类型（预设可选也可自填，含玄幻/悬疑/科幻/规则怪谈/权谋等）、一句话立意、故事梗概（**AI 根据世界观/地点/角色生成简介**）、每章字数下限/目标/上限、删除作品、AI 起名 |
| 角色 | 姓名、性别（男/女/其他，可自填）、年龄、长相、性格、身份、故事定位（主角/配角/反派…）、语言特征、补充；新增/编辑/删除；**AI 生成 / AI 修改** |
| 世界观 | 时代、地点、运行规则、势力、禁忌；**AI 生成 / 改写** |
| 重要地点 | 城市/城镇/村庄/建筑/区域/秘境/遗迹/据点等；**包含**（城市→街区→建筑）与**串联**（关联地点）两种关系；描述、氛围、规则/禁忌、秘密/剧情钩子；**AI 生成 / 修改** |
| 文风 | 直白粗俗 / 口语 / 标准 / 优雅 / 文学性；人物 vs 景物侧重；人物细分为语言/动作/外貌/心理（可多选）；第一/第三人称；完全按要求 / 标准 / 自由发挥；直入正题 / 铺垫 / 悬念；句长；额外要求；语感参考段；**AI 生成文风方案** |
| 分支 | 主线 / if线 / 前传 / 后传 / 外传 / 番外 / 自定义；每个分支必须单独填写**时间线**；分支可新增/编辑/删除，删除时章节迁回主线 |
| 章节 | 按分支分组、分支内独立章序；正文查看、手动写章、**AI 起草本章**、本章时间线、梗概与出场人物、字数实时校验；**编辑已有章节的分支/章序/时间线/标题/梗概/出场人物**，改分支或章序自动顺延相邻章节 |
| 对话 | `writer_start` 按会话开启写作模式；`writer_context` 取上下文；`writer_save_chapter` 落盘；`writer_recall` 检索前文；`writer_update` 改设定；`writer_status` 看进度 |

## 安装

要求：DeepSeek Harness（web profile），Node 22+。

```powershell
node install.mjs
```

脚本会：

1. 把插件复制到 `~/.dsh/plugins/dsh-writer-studio`；
2. 在 `~/.dsh/profiles/desktop/package.json` 的依赖与 `dsh.profile.bundles` 里登记；
3. 在 profile 的 `node_modules` 里建立目录联接。

然后**完全退出并重启 DeepSeek Harness**（不是刷新页面）。重启后在右侧栏的引导页能看到「写作台」。

卸载：从 profile 的 `package.json` 里删掉 `dsh-writer-studio` 依赖与 bundles 条目，删除 `node_modules/dsh-writer-studio` 联接和 `~/.dsh/plugins/dsh-writer-studio`，重启。作品数据在 `~/.dsh/writer-studio`，删不删由你。

## 安全

`/api/writer-studio/*` 的每条请求都由宿主的 `connection.requestRejection()` 统一认证：Host、Origin 与浏览器凭据任一不通过即返回 401/403，认证服务不可用时路由不注册。

## 使用

1. 打开右侧栏「写作台」，新建作品，**先定每章字数区间**。
2. 补角色、世界观、重要地点、文风（可让 AI 起草后再改）。
3. 去「章节」建分支（主线 / if线 / 前传 / 后传…），**给每条分支填时间线**。
4. 在新对话里点面板的「开启」，或直接说「开启写作模式」。
5. 对 AI 说「写 if线第 1 章」：它会先拿该分支的上下文包，再按字数与时间线写，最后用 `writer_save_chapter` 落盘。
6. 一章写完就停。看面板的分支章节列表，确认后再写下一章。

### 数据位置

```
~/.dsh/writer-studio/
  state.json                 # 书籍、分支、角色、世界观、文风、章节元数据、会话绑定
  books/<bookId>/chapters/   # 每章正文 markdown
```

`DSH_WRITER_HOME` 环境变量可以改写这个目录（测试/多实例用）。

### AI 模型

面板里的 AI 生成默认跟随**当前对话正在用的模型**：插件读取该会话最近一次请求的 `provider`/`model`（`requestHeader().config`），没发过请求时退回 agent 创建时的路由。没有额外设置时，不会切到宿主的全局默认模型。

只有想强制换模型时才需要在 `cordis.patch.yml` 里写 `config.ai`（`provider` + `model`，可带 `reasoningEffort`）；不写就保持「跟随对话」。

## 设计边界

- **一次只写一章**：技能与工具都要求写完停笔，不自动连写。
- **不替用户定字数**：开书时由用户给区间；AI 只按这个区间写。
- **不提供“解除内容限制”**：本插件解决的是长篇一致性与工作流，不包含绕过内容安全、法律或平台规则的功能。写什么由你和模型的服务条款决定。
- **AI 生成是可选的**：宿主没有 `subagents` 服务时，面板会给出可读错误，手动编辑与对话写作不受影响。

## 开发

```powershell
# 语法检查
node --check lib/index.js
node --check lib/client.js

# 用临时数据目录跑行为测试
$env:DSH_WRITER_HOME = "$PWD\.tmp-test"
node your-test.mjs
```

客户端是手写的 `window.__ModuleLoader__.load` 经典脚本，不需要构建步骤；改完 `lib/client.js` 后重启 DSH 生效。
